# Squad Routing

## Primary Routes

- Architecture, cross-cutting scope, reviewer decisions -> Ripley
- React UI, dashboards, filters, report views -> Dallas
- Node.js, Express APIs, ingestion services, SQL wiring -> Ash
- Test planning, edge cases, reviewer validation -> Lambert
- Azure Functions, hosting, deployment, environment settings -> Parker
- Final critical implementation review and challenge function -> Bishop
- Shared memory, decisions, session logs -> Scribe
- Backlog and follow-up monitoring -> Ralph

## Proposal-Specific Routing

- Azure OpenAI ingestion and ARM discovery -> Ash
- AI model availability UI and filter changes -> Dallas
- SQL shape decisions and schema cleanliness -> Ripley + Ash
- Rollout risk, regression coverage, open-question tracking -> Lambert
- Function/App Service execution split and infra impact -> Parker
- End-of-development critical review -> Bishop

## Default Rule

If a task spans more than one area, route through Ripley first and fan out to the specialists in parallel.
